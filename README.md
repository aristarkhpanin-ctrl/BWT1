# Лендинг «Системы водоподготовки BWT для резиденций, вилл с бассейнами и SPA»

Вёрстка по макету Figma под интеграцию в существующий сайт bwt.ru (Bitrix,
шаблон `bwt_2023_general`).

Семантический HTML5 + LESS по БЭМ + ванильный JS. Максимум переиспользования
готовых блоков сайта: своего кода — только то, чего на сайте нет.

---

## Запуск

```bash
npm install
npm run build      # собрать assets/less → assets/css/residence.css
npm run watch      # пересборка на лету
npm run serve      # локальный сервер на :8080
```

Либо просто открыть `index.html` в браузере — страница самодостаточна.

---

## Структура

```
index.html                  разметка лендинга (это и есть деливери)
assets/
  less/
    residence.less          точка входа сборки
    _vars.less              токены: цвет, шрифт, брейкпоинты, сетка, тени
    _mixins.less            медиазапросы, типографика, утилиты
    _base.less              базовые стили блока .residence
    blocks/                 по файлу на группу секций
  css/residence.css         собранный CSS (+ source map)
  js/residence.js           аккордеон, степпер, дропдаун, подключение плагинов
  img/                      50 изображений из макета, WebP, 4.8 МБ
  fonts/                    BWT Cyr 300/400/700 (только для превью)
vendor/                     копии боевых ассетов сайта — ТОЛЬКО для превью
  header-reference.html     разметка боевой шапки (62 КБ), для справки
```

### Что в `vendor/` и почему

Это локальные копии файлов с bwt.ru, снятые из HAR-записи страницы
`/business/`. Нужны, чтобы `index.html` открывался и выглядел правильно без
доступа к сайту. **На прод они не идут** — там эти же файлы уже подключены
шаблоном. При интеграции блок `<link>`-ов на `vendor/css/*` из `<head>`
удаляется целиком, остаётся только `assets/css/residence.css`.

---

## Интеграция: что сделать на проде

1. **Удалить** из `<head>` подключения `vendor/css/*` и из футера страницы
   `vendor/js/*` — на сайте они уже есть.
2. **Удалить** `@font-face` из начала `assets/css/residence.css` (или блок
   в `_base.less` перед сборкой): семейство `Cyr` объявлено в
   `local/templates/bwt_2023_general/template_styles.css`.
3. **Заменить** `<header class="residence-stub">` на штатный header шаблона.
4. **Футер** уже взят с сайта как есть (`<footer class="footer newFontCyr">`) —
   на проде выводится шаблоном, из `index.html` его можно убрать.
5. **Форма**: вернуть server-side поля `sessid`, `roistat_visit`, `uri`
   и обработчик Bitrix (`WEB_FORM_ID=7`). Имена полей и sitekey SmartCaptcha
   уже проставлены как на `/business/pools/wooden-pools/`.
6. **Видео кейса**: проставить ссылку в `data-video` у `.js-video`
   (VK Video, как на странице деревянных бассейнов). Пока атрибут пустой —
   постер просто не превращается в плеер.

## Принятые решения

### Сетка — штатная, без самодеятельности

Используется `.container` из `uikit.min.css` сайта. Ширины контента в макете
совпадают с ним один в один:

| Окно | `.container` | Контент | Макет |
|---|---|---|---|
| ≥ 1460 | 1340 | 1320 | 1920 |
| 1200–1459 | 1170 | 1150 | 1440 |
| 992–1199 | 990 | 970 | — |
| 768–991 | 100 % | без боковых полей | — |
| ≤ 767 | 100 % | 370 при 410 | mob |

Диапазон 768–991 оставлен как на сайте (контейнер без бокового паддинга) —
по согласованию.

### Шрифт

Семейство называется **`Cyr`** (не «BWT Cyr»), переключается классом
`newFontCyr` — так же, как у `pools-new-design-wooden` на сайте. Веса:
300 → `BWT Cyr - Light Text.ttf`, 400 → `BWT Cyr-Regular.ttf`,
700 → `BWT Cyr-BoldHead.ttf`. Файлы в архиве побайтово совпали с теми,
что раздаёт сайт.

### Цвет

Только штатные переменные сайта: `--bwt-dark-blue` (#00174B) и
`--bwt-pink` (#FF88BD). Второй розовый из макета (#F087B6) сведён
к `--bwt-pink` — по согласованию.

### Кнопки

- `btn btn__accent btn__round` — розовая «Заказать проект» в навигации;
- `btn btn__blue btn__round` — тёмно-синие CTA (на сайте `btn__accent-dark`
  это розовый, тёмно-синий даёт именно `btn__blue`).

### Мобильные варианты изображений

У 17 картинок в макете mob своя матрица обрезки: исходник тот же, но кадр
другой — под вертикальный формат. Если брать десктопный кроп и дожимать
через `object-fit: cover`, кадр уезжает (на баннере «Единая инженерная
логика» лицо оказывается вплотную). Поэтому такие картинки выгружены
вторым файлом с суффиксом `-mob` и подключены через
`<picture><source media="(max-width: 767.98px)">`.

### Что на мобильном отличается от десктопа по существу

Сверял mob-фрейм с 1920 не только по размерам, но и по составу:

| Блок | 1920 | mob |
|---|---|---|
| «Дом высокого класса» | текст слева | **текст по центру**, кнопка на всю ширину |
| Финальный CTA | картинка справа от текста | **картинка сверху**, квадрат 370×370, подложка во всю ширину экрана |
| Баннеры с фото | заголовок + абзац | **только заголовок** — абзацы в mob-макете не нарисованы |
| Карточка этапов | заголовок и лид слева | **по центру** |

Абзацы баннеров прячутся через `display: none`, из разметки не удалены —
поисковикам они по-прежнему видны.

### Осветление сверху у баннера «Единая инженерная логика»

На фото положены два одинаковых белых градиента (`#FFFFFF` 94 % →
прозрачный к 34 % высоты; на мобильном — к 22 %). Он растворяет верх
фотографии в белом фоне секции выше. Без него получается резкая граница.

### Степпер этапов — две разные раскладки

Это единственный блок, где макеты расходятся структурно:

- **1920/1440** — стрелка 64 │ лента цифр 621 │ стрелка 64, зазор 51,
  подпись под всем этим; блок 851px, прижат влево;
- **mob** — лента цифр во всю ширину, под ней подпись, стрелки уезжают
  в отдельный ряд по краям и меняют вид на белый круг (50 % прозрачности)
  с тёмно-синим шевроном; заголовок и лид карточки выключены по центру.

Реализовано одной CSS-сеткой с `grid-template-areas`, поэтому разметка
общая. Под активной цифрой точка гаснет — вместо неё розовый отрезок
шириной ровно с цифру.

### Библиотеки — только те, что уже на сайте

| Задача | Решение |
|---|---|
| Слайдер пространств | Slick |
| Лайтбокс галереи бассейна | Magnific Popup |
| Маска телефона | inputmask |
| Плавный скролл по якорям | pagescroll2id (на проде), свой фолбэк если плагина нет |
| Протяжка лент мышью | свой обработчик на Pointer Events |

С нуля написаны только **аккордеон FAQ** (готового на сайте нет — есть лишь
`.onepipe-faq h2`) и **степпер этапов 01–07**.

## Расхождения с макетом — осознанные

1. **Футера в макете нет** — взят с боевого сайта, по согласованию.
2. **FAQ нарисован только под 1440** и со всеми раскрытыми пунктами. Сделан
   аккордеон, все пункты закрыты по умолчанию, раскрываются по клику;
   состояния под 1920 и mob выведены по общей логике страницы.
3. **Опечатки в макете поправлены** в тексте: «прудама» → «прудами»,
   «Усадьбы и поместье» → «Усадьбы и поместья». Если нужно вернуть
   как в макете — правки в секции `#section-objects`.
4. **Ряды-ленты** (типы объектов, оборудование) в макете начинаются
   от левого края экрана и уходят за правый — реализованы full-bleed
   горизонтальной прокруткой, без привязки к контейнеру.
   Тянутся мышью, пальцем и трекпадом.
5. **Метаданные Figma местами врут — верим рендеру.** У подзаголовка
   героя API отдаёт `fontWeight: 700` и `textCase: UPPER`, а нарисован
   он обычным начертанием и обычным регистром. То же с заголовками
   карточек типов объектов (API 700, в макете 400). Веса подбирали
   замером: ширина строки и плотность пикселей в рендере макета
   сравнивались с эталонным рендером тех же строк шрифтом Cyr.
6. **Высота страницы**: 15 513 px против 15 552 в макете на 1920
   (−0,25 %).
7. **Заголовок карточки этапов на 320px** переносится в три строки
   вместо двух — текст физически не помещается в 232px при кегле 16.
   Висячих строк нет: перед тире стоит неразрывный пробел.

## Проверено

Chromium, 14 ширин — 320, 360, 375, 390, 414, 480, 600, 768, 900, 1024,
1280, 1440, 1600, 1920. Ни на одной нет горизонтального переполнения
и ошибок JS. Цифры степпера нигде не наезжают друг на друга
(минимальный шаг 35px при 320).

Подробно на 1920 / 1440 / 410:

- ширины контейнера и контента совпадают с макетами (1340/1320, 1170/1150, 370);
- поблочная сверка с рендером макета: карточка «Технологии» 601×548 при x=300,
  карточка CTA 1320×423 с картинкой 795 справа, фото бассейна 901×506 по центру,
  лента галереи 1465 — совпадают до пикселя;
- горизонтального переполнения нет;
- ошибок JS нет;
- аккордеон открывается и закрывается, по умолчанию всё закрыто;
- степпер листается стрелками и кликом по цифре, крайние состояния гасят стрелки;
- Slick инициализируется, 9 слайдов;
- маска телефона даёт `+7 (916) 123-45-67`;
- ленты типов объектов и оборудования тянутся мышью (`scrollLeft` меняется,
  клики по карточкам при этом не ломаются);
- степпер: под активной цифрой точка гаснет, вместо неё розовый отрезок —
  как в макете; карточка этапов 1320×468, лента цифр 464…1085.

Не проверено вживую: отправка формы и SmartCaptcha (нужен бэкенд Bitrix
и домен, зарегистрированный для sitekey).
